# UI 界面生成提示词

## 1. 使用说明

本文件面向 Figma AI、Galileo、Uizard、MasterGo AI、v0 类 UI 生成器及图片模型。先提交“全局设计系统提示词”，再按页面逐条提交。若工具不保留上下文，把全局提示词与单页提示词合并。

要求工具输出高保真产品界面，而不是营销海报：必须有真实组件层级、Auto Layout、交互状态、可访问文本和可实现的间距。生成结果只作为视觉与布局参考，最终 UI 仍按 Flutter/Tauri 组件实现。

## 2. 品牌与设计系统总提示词

```text
为一款名为“Sub2API Mobile”的开发者 AI 客户端和配套“Codex PC Companion”设计统一的产品 UI 设计系统。

产品气质：可靠、克制、专业、偏开发者工具；强调远程协同、连接状态、安全和可审计性。避免廉价的赛博霓虹、过量渐变、玻璃拟态、巨大装饰插画和聊天机器人玩具感。

视觉语言：Material 3 为移动端基础，桌面端采用紧凑型生产力工具布局。主色使用沉稳的 Indigo 600，成功/在线使用 Emerald 500，警告使用 Amber 500，错误使用 Red 500；中性色使用 Slate。亮色背景 #F7F8FC，暗色背景 #0F172A，卡片有轻微边框，不用重阴影。主操作按钮高度 48px，圆角 12px；普通卡片圆角 14px；状态胶囊圆角 999px。图标使用统一的线性图标库，2px 线宽。

字体：Android 使用 Roboto / Noto Sans SC；桌面使用 Inter / Noto Sans SC；代码、ID、模型名和金额使用 JetBrains Mono。中文正文 14-16sp，层级清楚，数字使用 tabular figures。

必须提供 Light 和 Dark 两套 token；符合 WCAG AA；触控目标至少 44x44；状态不能只靠颜色，必须配文字或图标。

全局组件：站点标识、用户头像、余额徽标、在线状态点、设备卡片、API Key 选择器、分组/模型选择器、公告角标、Markdown 消息、代码块、工具调用折叠卡、任务状态时间线、价格确认条、空状态、Skeleton、错误重试条、离线 Banner、确认弹窗、Toast、底部导航和桌面侧栏。

协同任务计费文案必须逐字使用“本次任务费用 $0.10 USD”或账务状态中的“$0.10 USD”；原需求中的“0.1 元”指 0.10 USD，不是 CNY。不得出现 ¥、CNY、汇率换算或“以站点配置为准”。普通聊天和 GPT Image 不使用这个固定协同费率，仍显示站点渠道计费提示。

所有屏幕都要覆盖：正常、加载、空数据、网络错误、权限不足、离线、危险确认中的关键状态。不要显示真实 API Key、JWT、邮箱密码或完整本机路径；示例 Key 只能显示 sk-••••8H2Q。

交付格式：组件化 Figma frame，使用 Auto Layout 和 8pt spacing grid；移动 Frame 390x844，桌面 Frame 1440x900；图层和组件命名使用英文语义名；文本内容用简体中文，预留中英文长度变化。
```

## 3. 移动端信息架构

底部导航 MVP：

1. 对话
2. Codex 协同
3. 公告
4. 我的

管理员登录后不要改变普通用户主导航；在“我的”中增加“管理控制台”入口，进入独立 AdminShell，便于后续扩展。

## 4. 移动端页面提示词

### M-01 启动与站点配置

```text
基于既定 Sub2API Mobile 设计系统，设计 Android 站点配置页，390x844。

场景：用户第一次打开 App，需要连接自己的 Sub2API 站点。顶部是低调品牌标识和标题“连接你的 Sub2API”，副标题解释数据直接连接自托管站点。主体是一张站点表单卡：站点地址输入框（示例 https://api.example.com）、自动补全 https、右侧“检测”按钮；下方显示三种检测状态组件：检测中、连接成功（站点名称、版本、HTTPS 安全标志）、检测失败（证书/地址错误和重试）。底部主按钮“继续登录”，仅检测成功可用；次要链接“局域网开发模式说明”。

增加“最近站点”区块，最多 3 项，显示域名、最后登录账号的脱敏邮箱、最近使用时间和删除菜单。不要出现多余插画。展示 Light 正常态以及 Dark 检测失败态两个 artboard。
```

### M-02 登录与 2FA

```text
设计 Sub2API Mobile 邮箱密码登录页和 TOTP 2FA 页，共两个 Android artboard。

登录页：顶部返回站点选择，显示当前站点域名和绿色 HTTPS 锁；邮箱、密码输入框，密码显示开关，“忘记密码”，主按钮“登录”。按钮下有小字说明“登录凭证仅发送到当前站点”。表单错误就地显示，支持服务器 Turnstile/条款提示区域但默认折叠。底部显示 App 版本。

2FA 页：标题“输入两步验证码”，展示脱敏邮箱、6 位等宽数字输入、倒计时/重新发送、返回登录；错误态不清空已输入前 5 位。整体专业、克制、键盘友好。
```

### M-04 普通聊天页

```text
设计高保真的 Android AI 聊天页，标题为本地 conversation，属于 Sub2API Mobile。

顶部：返回、可点击标题、模型/Key 两行小字、更多菜单。消息区包含：用户消息气泡；助手 Markdown 消息；带语言标签、复制按钮和横向滚动的代码块；流式生成光标；错误消息卡片（重试）；图片结果缩略图网格。助手消息不使用彩色大气泡，采用开放式内容排版。
```

### M-08 Codex 会话查询列表

```text
设计 Android 某一 PC 的 Codex 会话列表。

App Bar 显示设备名和绿色在线状态。顶部大搜索框，右侧筛选按钮；紧接一个醒目的主按钮“查询本机最新会话”，点击后变为带进度的“正在查询 PC…”。筛选支持工作目录、会话状态、是否归档。

生成正常列表、查询中 Skeleton、PC 在查询期间离线错误态。不要把 UUID 当作主视觉，只在详情辅助信息显示短 ID。
```

### M-09 Codex 会话详情与协同发送

```text
设计 Android Codex 会话详情页，这是产品最核心界面。

顶部：返回、会话标题、设备名与状态，右侧“同步”图标按钮；同步按钮旁显示上次同步时间。会话状态条显示“可写”“运行中”“外部终端占用”之一。

时间线用聊天式布局但能区分结构化事件：用户任务、Codex 最终回复、Reasoning 摘要、命令执行折叠卡（命令、cwd 脱敏、耗时、exit code）、文件修改卡（文件数与 diff 摘要）、工具调用、Plan 步骤、错误。工具输出默认折叠，避免巨量终端文本淹没页面。

底部输入：多行任务文本；左侧附件预留但 MVP disabled；右侧发送。输入框上方固定费用提示“本次任务费用 $0.10 USD”。点击发送弹出轻量确认：设备、会话、费用“$0.10 USD”、当前余额；提供“不再对本次会话询问”只能省略视觉确认，不能绕过服务端计费。

生成四种状态：可写空闲；Codex 流式执行；等待 PC 审批（Amber 横幅和“请在电脑确认”）；外部占用只读（输入框 disabled，操作“关闭原 Codex 后重试”与“创建副本，后续功能”）。
```

## 5. PC Companion 信息架构

桌面左侧导航：概览、会话、实时任务、审批、设置。底部固定账号、站点和连接状态。PC 工具是辅助端，不复制 Sub2API Web 管理后台。

## 6. PC 界面提示词

```text
基于统一设计系统，设计 Codex PC Companion 桌面首次启动流程，1440x900。

左侧 40% 为简洁品牌与三点价值：同一 Sub2API 账号、出站加密连接、使用 Codex 官方 app-server 协议。右侧为卡片式表单：站点 URL、邮箱、密码、登录按钮。登录后进入环境检查步骤：Codex CLI 路径、检测到的版本、app-server capability、系统 Keyring、网络连接，每项有 pass/warn/fail 和修复动作。最后设置设备名称并点击“连接此电脑”。

不要用大面积插画，不显示真实路径中的用户名，路径示例使用 ~/bin/codex。生成登录态与“Codex 版本不兼容”检查态。
```

### P-03 桌面会话管理

```text
设计 Codex PC Companion 会话管理页，1440x900，参考现代 IDE 的三栏布局但不要复制具体品牌。

左栏为会话搜索、工作目录筛选、状态筛选和会话列表；列表项显示标题、目录短名、更新时间、可写/外部占用/只读状态。中栏显示选中 thread 的结构化时间线：消息、命令、文件修改、工具卡。右侧 Inspector 显示 thread ID 短码、完整脱敏目录、Codex 状态、是否被当前 app-server 加载、移动端可见性、操作“刷新”“在终端打开”“显式创建副本”。
```

### P-04 实时任务

```text
设计 Codex PC Companion“实时任务”页，1440x900。

顶部显示当前 active command：来自 Android、会话标题、开始时间、收费由服务器处理的说明。中间为实时事件流，包含 plan、命令、文件修改、assistant 输出；右侧窄栏是 command 生命周期和 app-server 健康。底部有“中断任务”危险次级按钮，不提供绕过权限的操作。

页面要区分 queued、running、waiting approval、completed。若没有任务，显示安静的空状态和最近 5 条历史。信息密度高但不拥挤。
```

### P-05 审批中心

```text
设计 Codex PC Companion 审批中心，重点体现安全和明确决策。

左侧待审批队列，badge 显示类型：命令、文件修改、额外权限、用户输入。主面板显示来源会话、Mobile command ID、请求原因；命令审批展示 tokenized command、脱敏 cwd、网络/文件权限；文件修改展示统一 diff；权限请求列出允许的根目录和网络范围。

底部操作按 app-server availableDecisions 动态显示，例如“拒绝”“本次允许”“本会话允许”，危险的持久允许需要二次确认。不要默认选中允许，不要把“允许所有”设为主按钮。右侧显示倒计时/任务等待状态和“手机端正在等待电脑确认”。
```

### P-06 设置与诊断

```text
设计 Codex PC Companion 设置页，1440x900。

分区：账号与站点、设备名称、开机启动/最小化到托盘、Codex CLI 路径与版本、app-server 重启、同步隐私、日志级别、更新。隐私区用 toggles 表示“向手机同步工具摘要”“允许同步完整工具输出（默认关闭）”，并解释 Sub2API 默认不持久保存会话正文。
```


## 11. UI 交付检查

- 所有关键页同时覆盖加载、空、错误、离线和权限状态。
- `popup` 公告与普通 Dialog 视觉可区分但不过度打扰。
- 普通聊天与 Codex 协同在导航、颜色和消息事件形态上可分辨。
- 费用在发送前可见，held/settled/refunded 文字清楚。
- 外部占用会话不显示可用发送按钮。
- PC 审批决策与 app-server 提供的 available decisions 对齐。
- 管理员入口资源已预留，但不伪造尚未实现的数据。
- 设计稿中的示例 Key、ID、路径和邮件全部为脱敏假数据。
